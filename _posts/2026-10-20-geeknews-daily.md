오늘 GeekNews에서는 AI 에이전트를 직접 만들고, AI가 쓴 코드를 어떻게 믿을지 고민하는 글이 가장 많은 관심을 받았다. 순수 Python 약 300줄로 에이전트의 원리를 익히는 입문서, AI 코드를 이해하지 못한 채 배포하는 문제를 다룬 Ask HN 토론, 기술 개념을 움직이는 도해로 만드는 에이전트 스킬을 소개한다. 여기에 DeepSeek의 추론 엔진 공개와 실제 공격에 악용되고 있는 Plex 취약점 소식도 함께 정리한다.

## 1. Harness Engineering 101: Python 약 300줄로 배우는 AI 에이전트 구현

프레임워크나 SDK 없이 HTTP 요청부터 시작해 약 300줄짜리 코딩 에이전트를 직접 만들며 작동 원리를 익히는 입문서가 GitHub에 공개됐다. "LLM은 두뇌, 하네스는 몸"이라는 비유에서 출발해, 상태가 없는 LLM API에 매 턴 대화 전체를 JSON 배열로 보내고 그 배열을 만들고 지키는 프로그램을 하네스라고 정의한다. 16개 장은 저마다 실패 상황, 최소한의 수정, 그 수정에 드는 비용 순서로 짜여 있고, 도구 호출과 에이전트 루프에서 시작해 캐싱, 컨텍스트 관리, 하위 에이전트, MCP와 스킬, 훅, 가드레일, 디버깅, RAG까지 다룬다. 부록에서는 모델 라우팅, worktree를 이용한 작업 환경 격리, 재시도와 스트리밍을 설명한다. 실습 코드는 Python 3.10 이상에서 외부 패키지 없이 돌아가고, 기본 예제를 실행하려면 Anthropic API 키가 필요하다. 본문은 CC BY-NC-ND 4.0, 코드는 MIT 라이선스다.

**왜 중요한가:** 에이전트 프레임워크도 결국 기본 루프를 감싼 것이라는 점을 직접 만들어 보며 이해할 수 있어, 도구를 고르거나 문제를 디버깅할 때 판단 기준이 생긴다.

## 2. Ask HN: AI가 쓴 코드를 이해하지 못한 채 배포하는 문제, 어떻게 대처하나

AI 덕분에 배포 속도가 너무 빨라져 코드를 한 줄씩 검토할 수 없다는 한 Meta 엔지니어의 고민에서 시작된 Hacker News 토론이다. 많은 답변은 구성 요소의 역할과 인터페이스 같은 설계는 사람이 정하고 구현은 AI에 맡기되, 설계에 직접 관여하고 이해하고 승인하는 것이 핵심이라고 봤다. 구현 전에 에이전트가 모호한 요구사항을 질문하게 하거나, 설계서와 구현 계획을 먼저 검토하고 기능을 바꿀 때마다 아키텍처 문서를 갱신하게 하는 방법도 공유됐다. 테스트에 대해서는 실패하는 테스트를 먼저 확인하는 TDD를 권하면서도, 모델이 기존 테스트를 새 구현에 맞게 고쳐 버려 회귀가 생긴 사례를 들어 테스트 자체도 검토 대상이라는 지적이 나왔다. 구현 에이전트와 검사 에이전트를 분리하거나, 일부러 버그를 넣어 테스트가 이를 잡아내는지 확인하는 변이 테스트도 제안됐다.

**왜 중요한가:** AI 코딩이 일상이 된 지금, 어디까지 직접 이해해야 하고 무엇을 검증으로 대신할지에 대한 현업의 실제 방법이 모여 있다.

## 3. Anatomy: 기술 개념을 움직이는 입체 도해로 만드는 AI 에이전트 스킬

캐시, 연결 풀, 요청 제한 같은 기술 개념을 실제로 움직이는 기계나 장치에 빗대어 인터랙티브 도해로 만들어 주는 코딩 에이전트용 스킬이 공개됐다. 설명할 개념과 수치, 출력 형식을 지정해 요청하면 SVG로 부품과 배관, 음영을 그리고, 마우스와 키보드 조작에 따라 움직임과 표시 수치가 함께 바뀌도록 만든다. 결과물은 독립 실행 HTML, SVG 파일, React/Next.js 컴포넌트로 내보낼 수 있고, 불꽃이나 물, 빛 반사 같은 효과는 WebGL을 섞어 표현한다. 부품끼리 겹치거나 연결이 어긋났는지 검사하고 브라우저 스크린샷으로 결과를 확인하는 도구도 들어 있다. Claude Code, Codex, Antigravity, OpenCode, MiniMax Code에서 쓸 수 있으며 MIT 라이선스다.

**왜 중요한가:** 문서와 블로그, 교육 자료에서 말로 설명하기 어려운 시스템 동작을 직접 조작해 보는 시각 자료로 바꿀 수 있어, 에이전트 스킬의 쓰임새가 코드 작성 밖으로 넓어지고 있음을 보여 준다.

## 4. DeepSeek, 추론 엔진 DeepInfer 오픈소스로 공개

DeepSeek이 자사의 대규모 프로덕션 서비스를 구동하는 추론 프레임워크 DeepInfer를 Apache License 2.0으로 공개했다. 이번 버전은 오프라인 추론만 제공하며, 지원 모델은 DeepSeek-V4.1-Flash, 지원 하드웨어는 NVIDIA SM100 GPU와 Huawei Ascend 950 NPU다. FlashMLA, DeepGEMM, DeepEP 등 최적화 커널과 병렬 처리에 더해, 초안 토큰으로 디코딩을 가속하는 기능과 짧은 구간만 다시 처리해 프리필 작업을 줄이는 기능이 들어 있다. 배치 구성이 달라도 결과가 같은 배치 불변 추론과 결정적 샘플링은 NVIDIA에서만 지원하고, 정규식·JSON 스키마·EBNF 문법으로 출력을 제한하는 구조화 출력도 지원한다. 다만 KV 캐시 시스템과 복제본 간 부하 분산은 포함되지 않아, 완전한 서비스를 꾸리려면 이를 따로 갖춰야 한다.

**왜 중요한가:** 프런티어급 모델을 운영하는 회사가 실제 서빙 엔진을 공개한 사례로, 대규모 추론 최적화 기법과 재현 가능한 추론 구현을 직접 들여다볼 수 있다.

- [GeekNews](https://news.hada.io/topic?id=35703) · [원문 (GitHub)](https://github.com/deepseek-ai/DeepInfer)

## 5. Plex 취약점, 암호화폐 채굴기 설치에 실제로 악용 중

Plex Media Server 취약점이 실제 공격에 쓰여 암호화폐 채굴기가 설치되는 장면이 허니팟에서 관측됐다. Plex는 9월 1일 v1.43.2 이하 버전을 대상으로 중요 보안 업데이트를 공지했고, 여러 취약점을 연결해 원격 코드 실행을 달성하는 Plex2Shell 분석과 공격 코드가 10월 16일 공개됐다. 취약한 버전을 돌리던 허니팟에서는 10월 17일 오전 서로 다른 IP 3곳에서 들어온 악용 시도가 확인됐고, 외부 서버에서 파일을 내려받아 채굴기를 실행하는 동작이 잡혔다. 이후 관측에서는 다른 사람이 인터넷 트래픽을 쓸 수 있게 하는 프록시 프로그램 실행도 확인됐지만, 상세 분석은 아직 이뤄지지 않았다. 작성자는 처음에 외부 통신을 막아 둔 탓에 모든 공격의 페이로드를 확보하지 못해 관측 데이터가 불완전할 수 있다고 밝혔다.

**왜 중요한가:** 공격 코드가 공개되자마자 실제 악용이 시작된 사례로, 집이나 서버에서 Plex를 인터넷에 노출해 운영한다면 서둘러 업데이트해야 한다.
